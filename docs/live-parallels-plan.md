# План перехода: хост macOS → гость Parallels → окно Lineage 2

Дата плана: 2026-09-17. Цифр живых прогонов здесь нет.
Это явная команда открыть живой край **после** закрытого синтетического L1/L2
(ADR-0039, ADR-0040). H1 на SyntheticEnv по-прежнему не закрыта; S2 здесь
идёт по исключению дорожной карты («живая команда важнее незакрытого H1»),
не потому что H1 принята.

Игра названа: Lineage 2 в оконном режиме внутри Parallels Desktop.
Хроника Interlude (чат F44). Сборка клиента unknown (Q1). Q6: оператор
в мире на `LineageII Interlude Server`, персонаж BotEbaniy.

## Топология

Агент — процесс macOS. Гостевая Windows видна только как окно и как
приёмник OS-событий. В процесс клиента не входим.

```text
macOS host (M4 Max)
  ScreenCaptureKit  -->  l2_brain (кадр Frame,  не Observation с позой)
  l2_brain          -->  InputBackend (сначала dry-run, потом живой край)
         |                    |
         | L2F1 pipe          | только после этапа 3 и ADR на live
         v                    v
  окно Parallels VM    -->  гостевой рабочий стол / клиент в окне
  Windows guest             без инъекций, без патча, без перехвата учёток
```

Контроллер не вызывает захват и не вызывает HID. Как на стенде:
`FrameSource` и `InputBackend` снаружи политики.

### Что уже есть (не строить заново)

| кусок | где | ограничение |
|---|---|---|
| зонд SCK | `macos/CaptureProbe`, CLI `l2-brain capture` | self-test ≠ H7; не окно Parallels |
| кадр в Python | `SCKFrameSource`, pipe `L2F1`, формат `rgb8` | копии есть; zero-copy нет |
| профиль окна | `config/window_profiles/` | HUD координат нет |
| dry-run ввод | `DryRunInputBackend`, watchdog 250 мс | `dry_run=False` не конструируется (ADR-0035) |
| L2 спот | `SpotAutonomousAgent` + `TelemetryHub` | питается `sim_ground_truth`, не пикселями |
| L1 | `snn_v1` + замороженный `baseline_memory_v1` | не клиент |

### Чего в репозитории нет и нельзя выдумать

- драйвер Virtual HID / VirtIO в госте;
- готовый адаптер `GuestHID`;
- zero-copy BGRA→NumPy (сейчас stdout pipe);
- замер «≤ 3 мс от рендера гостя до NumPy»;
- парсер Classic UI Lineage 2;
- живой `InputBackend`.

Соседняя заметка N1 (скрытое окно Parallels, ошибка −3811) — **не факт
этого репо**. Повторять только видимое окно нашим зондом.

## Что план не обещает

- неуязвимость для античита: процесс на хосте не равен «невидимости».
  Гость и клиент по-прежнему видят окно, ввод и типичный VM-контур;
- фиксированную задержку и «не застревает»;
- перенос 4 фрагов со спота (F39) в стартовую локацию;
- обход защиты, маскировку автоматизации, инъекции, патч клиента,
  перехват учёток (ADR-0002).

Вариант «скрипт ввода внутри Windows» — не гостевой агент *в процессе
игры*. Если до него дойдём, это отдельный userspace-процесс и отдельная
ADR. По умолчанию держим ввод на хосте (вариант A).

## Этап 1 — захват окна Parallels (S2 на конкретном источнике)

**Цель.** Стабильный поток сырых кадров видимого окна VM, без политики
и без ввода.

**Делаем.**

1. Список окон: `l2-brain capture list`. Зафиксировать title/PID окна
   Parallels (не «любое окно», не скрытый стол гостя).
2. Профиль `config/window_profiles/parallels_l2.json`: пока полный кадр,
   маски пустые. Координаты HUD сюда не вписывать до этапа 2.
3. Запись 30 с видимого окна: интервал, drop, чёрные кадры, resize.
   JSON в `docs/evidence/live-s2/`.
4. Тот же замер на self-test / обычном окне macOS как контроль (уже
   был короткий self-test, F12 — не замена).
5. Бюджет «≤ 3.0 мс render→NumPy» — **гипотеза для замера**, не критерий
   приёмки этапа. Приёмка по H7: медиана интервала ≤ 50 мс, black < 0.05,
   drop < 0.10 на 30 с. Если медиана > 80 мс или нужен скрытый стол —
   H7 отклонена, в контур кадр не ставим.

**Не делаем.** ctypes к ScreenCaptureKit; shared memory «на всякий случай»;
захват свёрнутой VM как основной путь; подключение кадра к `SpotAutonomousAgent`;
zero-copy до цифры, что pipe — узкое место (ADR-0014).

**Критерий.** Есть evidence JSON с окном Parallels, H7 принята или явно
отклонена. `evaluate` по умолчанию SCK не включает.

**Команды (ориентир, не прогон этого файла):**

```text
l2-brain capture permission
l2-brain capture list
l2-brain capture record --window-id <id> --out docs/evidence/live-s2/parallels-30s
```

**Следующий код после утверждения плана — только этот этап.**

## Этап 2 — семантика HUD с пикселей (не GT симулятора)

**Вход.** Этап 1: поток с окна Parallels принят (H7).

**Цель.** Снять `sim_ground_truth` с боевой шины. `TelemetryHub` получает
`HealthUpdate` / `TargetState` от парсера кадра. В `Observation` по-прежнему
нет позы, дистанции, HP как полей симулятора.

**Что читать** (Classic UI, координаты только в игровом профиле, не в
`control/`):

1. свои HP/MP/CP — доля заполнения цветовой маской;
2. окно цели: есть рамка/имя, доля HP, смерть (ноль или пропажа рамки);
3. слот хоткея — грубый кулдаун (есть/нет), не парсер всех бафов.

Дальность до моба с кадра **нет**. `RangeCue.privileged` для сима
остаётся стендовым. В живом контуре атака идёт по правилу «рамка есть +
свой выбор дистанции по размеру силуэта / пробному F2», это отдельная
калибровка, не «1.8 м из GT».

**Не делаем.** OCR всего чата как сенсор политики; pcap; память процесса
гостя; вшитые пиксели в общий энкодер `navigation_v1`.

**Критерий.** На записанных кадрах (не обязательно в петле) парсер даёт
стабильные события шины. Ложные срабатывания «цель есть / цели нет»
зафиксированы. Политика ещё не нажимает клавиши в клиент.

2026-09-17: механизм и синтетика закрыты (F41, ADR-0042). Кадр
оконного Interlude есть (F44). Ход 39: ROI полос измерены (F45).
Ход 40: смерть ≠ сброс (F46, ADR-0046). Пачка кадров и перетаскивание
виджета не закрыты. `sim_ground_truth` на стенде не снимали.

## Этап 3 — мост ввода (S3), сначала не в игру

**Вход.** Этап 1 принят. Dry-run лог по-прежнему эталон. Живой край —
новая ADR, снимающая запрет `dry_run=False` **только** для выбранного
транспорта.

**Порядок вариантов.**

1. **A (сначала):** события macOS в окно Parallels (`CGEvent` / эквивалент
   из отдельного актуатора). Агент остаётся целиком на хосте. Нет софта
   в госте.
2. **B (если A не доставляет события в гостевой фокус):** userspace-слушатель
   в Windows (сокет/pipe с хоста) → `SendInput`. Не драйвер, не VirtIO-HID
   «потому что так нарисовано», не код внутри `L2.exe`.

Watchdog 250 мс и kill-switch переносятся на живой актуатор. Потеря
фокуса окна Parallels = `release_all` + блок новых команд. Устаревший
кадр блокирует отправку.

**Критерий.** Блокнот или поле чата **вне клиента игры**: `HoldKey("w")`,
клик, `F1`–`F3` нажимаются и отпускаются, залипаний нет, `emergency_stop`
глушит очередь. `hid_sent` в логе честный. p50/p95 `act_ms` записаны.
H8 ещё не закрыта (нет полного контура).

2026-09-17: механизм ADR-0043 есть. Ход 37: live в Notepad без `L2.exe`,
`hid_sent=true`, stuck=0, watchdog отпустил `w` (F43). S4 не открыт.

**Не делаем.** Ввод в клиент до стопа на Блокноте. Скрытие того, что ввод
автоматический. Автологин.

## Этап 4 — короткий замкнутый прогон в клиенте (S4)

**Вход.** Этапы 1–3 закрыты, Q6 разрешён, человек явно пишет «S4 открыт».

**Цель.** Один узкий навык на тестовом персонаже, не гринд и не «автоном
на споте как на стенде».

Черновик сценария (клавиши — из профиля, не из этого абзаца, пока Q5
не измерен):

1. `TargetSelect` (кандидат: F1 / next);
2. парсер подтверждает рамку цели;
3. L2: APPROACH + пробная атака (кандидат: F2);
4. парсер видит падение HP цели;
5. короткий `Pickup`;
6. сброс (Escape) и стоп эпизода.

Лимит: десятки секунд, ручной надзор, kill-switch под рукой.
Успех — «события HUD и ввода согласованы в логе», не «3 моба подряд»
и не F39.

**Не делаем.** Часовой фарм, квесты, несколько окон, обучение на живом
вводе в том же шаге, что первый контур.
