# План H15 — абляция каналов

Гипотеза: на одном каталоге `nav-sim-v1` seed=0 контроллер с `Observation.navigation` даёт Δ success ≥ 0.15 против того же контроллера с одним `color_blob`.

Отклоняем, если Δ success_rate < 0.15. Наличие `NavigationEncoder` и метки `approach`/`camera_turn` гипотезу не закрывают.

## База и независимые переменные

- База: `color_blob`, память включена, каналы политики не используются (`navigation is None`).
- Сравнение: `navigation_v1` с наборами `target` / `target_flow` / `target_expansion` / `all`.
- `all` одновременно — снимок текущего контроллера после `repair-20260917`. Это не замена F14/F15.

Независимые: энкодер и набор каналов, которые видит политика. Остальное одинаково.

## Контрольные условия

- Каталог `suite=frozen`, seed=0, 60 эпизодов, 200 тиков.
- `BaselineConfig` общий, `recovery=True` во всех руках (не смешивать с H16).
- Абляции — после encode. Оценщик зрения считает сырой кадр.
- `target`: пеленг/пятно есть, поток и расширение политике не подаются.
- `target_flow`: пеленг + сектора/поток, расширение = 0.
- `target_expansion`: пеленг + расширение, поток и сектора обнулены.
- Один прогон на условие: тот же протокол, что F14/F15. Три независимых реплики не входят в бюджет.
- Held-out F14 не независим; в отчёте `held_out_independent=false`. Подбор по held-out не делаем.

## Метрики

- Главная: `success_rate`, Δ к blob.
- Рядом, не как критерий H15: outcomes/causes, miss, `infer_ms` отдельно от полного тика, события блокировки.
- Не обещать «не застревает».

## Сцены

Полный frozen-каталог. Среднее по лёгким сценам не прячет тупики: в summary есть таблица по именам.

## Команда

```text
.venv/bin/python tools/h15_ablation.py docs/evidence/h15
```

Отказывается перезаписывать `summary.json`. F14/F15 не трогает.

## Будущие JSON

`docs/evidence/h15/{blob,target,target_flow,target_expansion,all,summary}.json`

Цифр в этом плане нет: прогон ещё не выполнен.
