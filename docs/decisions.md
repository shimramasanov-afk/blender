## ADR-0084 — переразметка увеличенного StatusWnd

**Дата.** 2026-09-18  
**Статус.** Принято (код + unit + кадр hod95 + live R2 PASS).

**Контекст.** Оператор увеличил графики своего HP и HP моба.
Старые named ROI (self_hp 316,205,404,211) смотрели в землю.
`TARGET_BAND_MAX_H=16` и жёсткий `x0=0.16` резали широкий поиск.

**Решение.**

1. Self CP/HP/MP в `parallels_l2.json` с кадра
   `client-reference-hod95.png` (31,151,582,155 и соседние).
2. Recover своего статуса: кластер из трёх полос, самый широкий
   X-кластер, не крошки слева.
3. Recover цели ищет красные полосы по всему верху и вычитает
   свой виджет. Высота полосы до 28 px.
4. Named first-to-last только если заливка ≥0.70; иначе
   left-aligned. Sliver-ROI уступает recover.

**Последствия.** Старый F45 target_hp не перемеривали: на hod95
окна цели не было. Кадр без цели не доказывает lock моба.

**Отвергли.** Считать любой широкий красный слева целью.
Переписывать F45 evidence.

## ADR-0083 — F3 после слепого F2, без кредита килла

**Дата.** 2026-09-18  
**Статус.** Принято (код + unit).

**Контекст.** Лут шёл только после `killed=True`. Слепой F2
убивал в мире, JSON килл 0, `loot_skill_runs=0`.

**Решение.** Если blind engage послал F2 и не зачёл килл —
пауза дропа и `loot_target` (F3). `kills_completed` не растёт.
Килл по-прежнему HUD-смерть или `blind_melee`.

**Отвергли.** Любой F2 = килл (это уже отвергнуто ADR-0082).

## ADR-0082 — килл по контакту, если пластины нет

**Дата.** 2026-09-18  
**Статус.** Принято (код + unit). Live после правки не гоняли.

**Контекст.** Live R2: оператор видел киллы, JSON — 0.
`f2_input_count=55`. Парсер: `target_hp=0` / ложный lock, `_saw_lock`
не ставился, килл не зачитывался, F3 не слали.

**Решение.**

1. Плоское коричневое поле широкой ROI — не пластина.
2. Поиск цели не берёт колонку своих полос.
3. Слепой F2 без живого лока — `no_hud_lock` через 5 с, даже если
   парсер держит «труп».
4. Если за этот F2 своё HP упало ≥ `ENGAGE_DAMAGE_EPS` — F3 и килл
   `via=blind_melee`. Это контакт, не GT-смерть.

**Последствия.** Несколько волков за одно окно F2 дадут один килл.
Пустое поле без дропа HP по-прежнему roam. Не LIVE-PROVEN.

**Отклонено.** Писать в JSON киллы «потому что оператор сказал».
Считать любой F2 киллом.

## ADR-0081 — F2 без пластины цели

**Дата.** 2026-09-18  
**Статус.** Принято (код + unit). Live HID после правки не запускался.

**Контекст.** Live R2: F1 подсвечивал мобов, парсер не видел окно
цели, `wait_lock` не отпускал F2, персонаж уходил в roam.
`f2_input_count=0`. Подсветка 3D ≠ lock HUD.

**Решение.**

1. После SCAN без лока — `AttackTarget(require_lock=False)`: двойной
   F2, до 5 с, затем roam если живого лока так и нет.
2. Слепой старт не требует `target_locked` и не отказывается из-за
   `target_dead` на пустой/чужой пластине.
3. Килл только если сначала был живой lock (`_saw_lock`).

**Последствия.** Пустое поле тратит 5 с на воздух, потом roam.
Килл без пластины по-прежнему не засчитается. Не LIVE-PROVEN.

**Отклонено.** Ждать новую парковку F45 перед любым F2. Считать
3D-подсветку локом. Prompt 8.

## ADR-0080 — серия R1/R2, не повтор F82/F85

**Дата.** 2026-09-18  
**Статус.** Принято. Live R1/R2 по флагу есть (Ход 95).
Снимок: `docs/live-runtime-after-prompt7.5.md`.

**Контекст.** После Prompt 6–7 цепочка LiveRuntime есть только в unit.
Нужна минимальная live-валидация без Task layer.

**Решение.**

1. Новые факты — `docs/evidence/live-agent-runtime/`, идентификаторы
   R1 (NPC, один пункт) и R2 (combat, cap 3).
2. Флаг `--runtime-validation`. Default CLI без флага не менять.
3. Cursor не запускает `--live --danger-confirmed`.
4. Не писать `LIVE-PROVEN` до JSON прогона.

**Последствия.** F82/F85/F86 остаются старым каноном. Verdict
`docs/live-agent-runtime-validation.md` — только после ручного прогона.

**Отклонено.** Переписать F85 как «тот же прогон». Обход всех 6 пунктов
на первом runtime test. Сразу 10 фрагов.

## ADR-0079 — probes оркеструют LiveRuntime, live ещё нет

**Дата.** 2026-09-18  
**Статус.** Принято (код + unit). Live HID этим слоем не доказан.

**Контекст.** После каркаса Prompt 0–5 оба старых live-сценария всё
ещё слали HID сами. Prompt 8 (Task layer) без общего runtime на этих
сценариях дал бы красивую бумагу. Оператор: сначала снимок, не Prompt 8.

**Решение.**

1. `run_npc_dialog_probe` и `run_integrated_spot` создают один
   `LiveRuntime` и вызывают skills. CLI не удалять.
2. F5-путь не использует `OpenNpcDialog` (там F2). via_chat — использует.
3. Restart захвата остаётся у NPC probe (`recover_capture`). Spot на
   `capture_lost` абортит, как раньше.
4. Prompt 8 не начинать, пока оператор не выберет live validation
   или Task layer.
5. F82/F85 не переписывать и не объявлять «доказанными заново».

**Последствия.** `pytest` 358 passed. Живого прогона после миграции нет.
Следующий риск — расхождение unit и клиента.

**Отклонено.** Считать миграцию live-proven. Сразу писать
`GuideInteractionTask`. Подключать Frozen / SNN / MaleCNS.

## ADR-0078 — LiveRuntime и Skill, probes пока канон live

**Дата.** 2026-09-18  
**Статус.** Принято (каркас). Live HID этим слоем не доказан.

**Контекст.** Живой край — отдельные CLI-зонды без WorldState и
без tick-навыков. Нужен слой, который можно проверить как runtime,
а не как переименование `run_npc_dialog_probe`.

**Решение.**

1. `Skill` с `start` / `tick` / `cancel` и `SkillStatus`.
2. `WorldState` + `PerceptionHub` без импорта input backend.
3. `LiveRuntime` исполняет **один** skill за раз; HID только через
   существующий `CGEventInputBackend`.
4. CLI `agent-live` по умолчанию observe-only.
5. Существующие probes не удаляются и не обязаны вызываться из
   runtime. Миграция probe → skills — отдельные шаги.

**Последствия.** F82/F85/F86 остаются evidence зондов. Frozen L1,
`sim/`, MaleCNS не трогали. `Circuit.run()` без HID.

**Отклонено.** Считать победой обёртку `def start_skill(): return run_integrated_spot()`.
Planner, OCR, quest loop, второй HID backend.

## ADR-0077 — сетка в госте 2560×1600, оверлей на окно хоста

**Дата.** 2026-09-18  
**Статус.** Принято.

**Контекст.** Оператор: экран 2560×1600. Хост Mac — 2056×1329
логических, окно Parallels 2056×1290, SCK 4112×2580. Слоты в
пикселях хоста не совпадают с `WindowsInfo.ini` гостя.

**Решение.**

1. `layout_slots.ref_window` = `[2560, 1600]`.
2. Слот А `[60, 140, 400, 520]`, слот Б `[2140, 140, 360, 480]`
   (`w-420`). Габариты виджетов те же.
3. Оверлей и детектор масштабируют слот на фактическое окно /
   кадр через `box_on_frame`.
4. `expected_size` хоста 2056×1290 не меняем — это окно Mac.

**Последствия.** F86 (детекция на старом слоте Б) не
переписываем. После посадки окон нужен новый прогон
`layout-slots`. Q5 не закрыт.

**Отклонено.** Сетка в пикселях окна хоста 2056×1290 как
канон для WindowsInfo.ini.

## ADR-0076 — живой оверлей рамок, слоты — цели парковки

**Дата.** 2026-09-18  
**Статус.** Принято. Оператор видит рамки на окне.

**Контекст.** Ход 86 сохранил PNG. Оператор ждал рамки *поверх*
окна игры, чтобы сам перетащить виджеты. Слот Б в ADR-0075
был сдвинут на текущий инвентарь — это не цель парковки.

**Решение.**

1. Слоты снова цели: А `[60, 140, 400, 520]`, Б
   `[1636, 140, 360, 480]` (`w-420`).
2. CLI `layout-overlay`: прозрачное окно хоста над Parallels,
   клики навылет, без HID. `Ctrl+C` или `--seconds`.
3. `layout-grid` PNG остаётся снимком, не заменой слоя.
4. Занятость (кромка / std) из ADR-0075 действует *после*
   посадки окон в рамки. F86 не переписываем.

**Последствия.** Q5 не закрыт. Скилы/макросы не сажали.
Слой не инъекция в клиент.

**Отклонено.** Только PNG. Подгонка слота Б под текущий
инвентарь как «сетка».

## ADR-0075 — жёсткая сетка слотов UI, закрытие Escape

**Дата.** 2026-09-18  
**Статус.** Принято. Живой прогон: F86.

**Контекст.** Поиск произвольных окон по кадру даёт ложные HTML и
клики в землю. Клиент L2 помнит координаты в `WindowsInfo.ini`.
Проектный слот Б `[w-420, 140, 360, 480]` попал в траву: Tab
открыл инвентарь ниже.

**Решение.**

1. Экран — фиксированные слоты в `layout_slots` профиля, не
   динамический поиск рамок.
2. Слот А (диалог/квесты): `[60, 140, 400, 520]` в окне 2056×1290.
3. Слот Б (инвентарь/скилы/макросы): фактическая стоянка
   инвентаря Interlude `[1592, 650, 342, 307]`.
4. Занятость: светлая кромка заголовка (luma ≥80) плюс тёмное
   тело, либо std тела ≥20. Плоская тёмная трава не окно.
5. Стек `WindowManager`: `Escape` закрывает активное; до боя
   двойной Escape, если слот занят. Крестик мышью не ищем.
6. Калибровка: `layout-grid` → `run/layout_guide.png`.

**Последствия.** Q5 не закрыт. Скилы/макросы в слоте Б не
мерены. Перетаскивание окон срывает детектор. SCK timeout
зонда 4.0 с (0.8 с ронял первый кадр).

**Отклонено.** Поиск окон по всему кадру. Проектный слот Б
на пустой траве y=140. Только «тёмный пиксель заголовка».

## ADR-0074 — F2-подбег и меню только в левой панели

**Дата.** 2026-09-18  
**Статус.** Принято. Живой прогон: F85.

**Контекст.** Ход 84: `/target` лочит, клики по сетке уходят в
землю, синий маркер цели давал ложное HTML. Оператор: ники
белые. F2 на мирном NPC на этом стенде — подбег, не фарм.

**Решение.**

1. После `target_locked` на имени — один импульс F2, пауза 2.0 с,
   один ЛКМ в (0.50, 0.48). F1/F3/F4 нет. Слот не F2.
2. Ссылки только в левой панели `x∈[0.05,0.42]`, `y∈[0.20,0.85]`.
   Геометрия полосы: `w≥40`, `8≤h≤25` (масштаб к высоте кадра),
   `w/h≥2.5`. Центр кадра маскируется.
3. Обход: снимок `extract_menu_items`, клик k, 600 мс, Escape,
   400 мс. Закрыто — снова F2 + ЛКМ.

**Последствия.** ADR-0073 (чат-таргет) остаётся. Запрет F2 из
ADR-0071/0072 для этого зонда снят только после лока по имени.
Q5 не закрыт. OCR пунктов нет.

**Отклонено.** Сетка кликов по кадру. Поиск ссылок в центре.
Золотые ники как прицел. F2 до лока.

## ADR-0073 — таргет NPC через `/target` в чате

**Дата.** 2026-09-18  
**Статус.** Принято в коде. Живой прогон h не выполнен:
окно 16372 `on_screen=false`, скрытый стол не источник.

**Контекст.** Макрос F5 на каждого квестового NPC не масштабируется.
F83: F5 лочит. Оператор открывает диалог кликом по модели.
Детектор сначала промахнулся мимо тёмного HTML слева, затем дал
ложный SUCCESS по золотым никам. SCK после ЛКМ с HID-tap
закрывал stdout.

**Решение.**

1. `io/chat_commander.py`: Escape → Enter → `/target <Name>`
   (25 мс/символ, Shift для A–Z) → Enter. Нет лока за 500 мс —
   снова Escape. Имя только печатный ASCII.
2. После лока — ЛКМ в нижней трети кадра. PID-only, без
   `CGEventPost` на хост. Координата клампится в окно.
3. `html_links`: ≥2 синих кластера, не золотые ники.
4. Успех h: диалог был закрыт → открылся после клика по модели.
   Одна синяя ссылка, Escape. F1–F4 нет.

**Последствия.** Q5 не закрыт. Квестовый текст не читается.
SCK после PID-only клика живьём не измерен. ADR-0072 для клика
по модели остаётся; точка 0.50/0.55 заменена нижней третью.
F5-макрос для этого зонда не путь по умолчанию (`--via-chat`).

**Отклонено.** Слот на каждого NPC. HID-tap ЛКМ. Золото как
признак окна. Захват скрытого окна Parallels.

## ADR-0072 — диалог NPC открывать ЛКМ по модели

## ADR-0071 — мирный зонд HTML-диалога NPC

**Дата.** 2026-09-18  
**Статус.** Принято

**Контекст.** F82 закрыл тактический спот 10/10. Для L3 нужен

**Последствия.** F83: лок после F5 есть, окно за 8 с не открылось
для детектора. JSON `npc-dialog-probe.json`. Квестовые ветки не
читаются. Frozen L1 / `sim/` не менять.

**Отклонено.** Повторный F2 «для разговора». OCR. Автономное

## ADR-0070 — серия 10 фрагов, агро по среднему HP

**Дата.** 2026-09-18  
**Статус.** Принято

**Контекст.** F81: 5/5 за 94.6 с, L1 0, разворот 1, агро 0.
Порог «один тик −0.02» не сработал. Кап 5 закрывал серию.

**Решение.**

1. Кап серии 10. Таймаута нет. Стоп: `kills==10` или
   `self_hp<0.10`. F4 нет.
2. Агро: кольцо 5 тиков `self_hp`. Триггер, если текущее ниже
   среднего предыдущих на ≥0.015 и (нет лока или цель без урона
   >2.5 с). Дальше Escape → F1 → двойной F2.
3. L1 и разворот — как ADR-0069. Пустой roam считают с последнего
   килла, не за всю сессию.
4. В JSON дубли: `total_time_sec`, `avg_combat_sec`, `u_turns`,
   `aggro_triggers`, `stuck_keys`. Поиск в `frags` — стена цикла.

**Последствия.** F82: 10/10 за 150 с, L1 0, агро 2, разворот 2.
JSON `spot-series-10-stable.json`. Frozen L1 / `sim/` не менять.

**Отклонено.** Один тик −0.02. Суммарный roam-лимит на всю сессию.
Банки F4.

## ADR-0069 — агро-перехват, жёсткий L1, серия без таймера

**Дата.** 2026-09-18  
**Статус.** Принято

**Контекст.** F80: 7/10, abort `self_hp_low`. Длинные бои 12–14 с:
персонаж шёл к дальней цели, игнорируя бьющего. L1 сработал 60 раз
на траве (`expansion≈0`). TASK указал `tactical.py` и ADR-0066;
оба заняты другим смыслом.

**Решение.**

1. Живой контур остаётся `live/spot_loop.py`. `tactical.py` /
   Frozen L1 / `sim/` не трогать.
2. Агро: падение `self_hp` < −0.02 и (нет лока или цель без урона
   >2.5 с) → Escape → F1 → двойной F2. Счётчик
   `aggro_interrupts` только при новом локе.
3. L1 unjam только в COMBAT: F2 без урона по цели >3 с и
   `flow_magnitude<0.01` шесть тиков подряд. Peel 350 мс, без `w`.
4. Три пустых ROAM → разворот 2×450 мс + 3×`w` 500 мс, сброс
   счётчика поиска. Кап пустых roam 15.
5. Кап серии 5. `timeout=None`. Аварийный стоп `self_hp<0.10`.
   F4 нет.

**Последствия.** Номер ADR-0066 не переиспользовать. F81: 5/5
за 94.6 с, L1 0, агро 0, разворот 1. JSON
`spot-aggro-validation.json`.

**Отклонено.** Крутить `tactical.py`. L1 по одному `expansion==0`.
`w` в COMBAT. Непрерывная стрелка 900 мс (ADR-0064). Банки F4.

## ADR-0068 — живой L1-рефлекс + L2 FSM, не Frozen 52/60

**Дата.** 2026-09-18  
**Статус.** Принято

**Контекст.** H8 закрыта. Нужна серия до 10 фрагов с поиском.
Frozen `baseline_memory_v1` и `sim/` не открыты. H17: `w` ≤800 мс.
ADR-0065 уже занят (KLT/coarse).

**Решение.**

1. Живой контур — `live/spot_loop.py` + CLI `s4-integrated-spot`.
   Не `tactical.py` / `spot_agent.py` (синтетический стек).
2. На тике: SCK → `HUDParser` и `NavigationEncoder`. L1 peel 350 мс

**Последствия.** Прогоны в [hod14-report.md](evidence/hod14-report.md). Ворота 84 тика, дропы 5/5, коридор 5/5. Ловушки и `open_goal` живы. Полный 60 не измеряли.

**Отклонено.** Глобальный порог < 0.12. Ветки по имени сцены. Карта/вейпоинты. Лечить ворота recovery на `dead_end`. Metal/MPS. Считать ход 14 новой базой F14.

## ADR-0019 — Абляции H15 на стороне политики

## ADR-0017 — Явная кратковременная память и восстановление

**Дата.** 2026-09-16  
**Статус.** Принято

**Контекст.** Нужны состояния рабочей памяти и выход из застревания до рекуррентной реализации. Координатная карта в политике v1 запрещена. Застревание нельзя определять только малым оптическим потоком.

**Решение.** `ShortTermMemory`: недавний пеленг, сторона обхода, уверенность в продвижении, накопитель отсутствия продвижения, последние попытки. Ситуации: stand / camera_turn / goal_like / unreliable / blocked / move. Застревание — связка «команда вперёд + нет продвижения + повтор структурированной сцены + время». Повтор пустого неба не считается. Восстановление явное: меньше вперёд, разворот на месте, удержание попытки, смена знака, стоп после трёх неудач. Не биологический механизм. GT только в оценщике.

**Последствия.** Каталог seed=0 совпал с F14: 23/60, ловушки 10/10 ticks_p50=117.5, простые 13/15. GT-окон неподвижности 0, восстановление не включалось. Улучшение ловушек не подтверждено, регрессии нет. Сравнение с рекуррентной памятью ещё впереди.

**Отклонено.** Карта координат в политике. Signed reverse `forward`. Считать низкий поток застреванием. Объявлять биологию. Ветки по имени сцены.

**Пересмотр.** После рекуррентной реализации на том же каталоге и seed, либо на наборе с ненулевыми GT-окнами застревания.

## ADR-0016 — Прозрачный базовый контроллер до SNN

**Дата.** 2026-09-16

**Решение.** `BaselineController` на `Observation` + `NavigationChannels`. Закон — взвешенная сумма конфигурируемых вкладов. Короткая память стороны и пеленга, не веса. **Отклонено.** Условия под отдельные карты. Обязательная полная скорость. Считать отсутствие потока стеной. Обучение в этом контроллере.

## ADR-0015 — Интерпретируемый VisualEncoder без детектора объектов

**Дата.** 2026-09-16  
**Статус.** Принято

**Контекст.** Нужны измеримые сенсомоторные каналы (яркость, контраст, Δяркости, поток, расширение, пеленг цели, уверенности). Крупная модель объектов по умолчанию запрещена заданием. Color-blob остаётся входом mock-контура.

**Решение.** `NavigationEncoder` (`l2_brain.vision`): рабочий кадр 48×32, сектора 5×3, два масштаба (весь кадр и низ). Поток — эталонный block-match SAD с оценкой текстуры и штрафом за большой сдвиг. Расширение — отдельный поиск масштаба, принимается только при достаточной уверенности. HUD и оверлеи — только из `WindowProfile`. Команда — prior гипотезы, не измерение. Нет потока ≠ свободный путь. Диагностика PPM по флагу, не в синхронном пути политики. Стартовый размер выбран после `vision bench`: 32×24 не отделяет подход от поворота на стенде; 64×48 дороже и хуже на синтетике.

**Последствия.** `Observation.navigation` опционален. Mock/SCK контур по умолчанию не переключали. Польза в замкнутой политике не заявлена.

**Отклонено.** YOLO/детекторы по умолчанию. Считать отсутствие потока проходимостью. Принять 32×24 только из-за меньшего `encode_ms`.

**Пересмотр.** После сравнения политики с/без этих каналов или если 36 мс/кадр не влезает в бюджет тика.

## ADR-0014 — ScreenCaptureKit через stdout pipe

**Дата.** 2026-09-16  
**Статус.** Принято

**Решение.** Расширить `.build/capture-probe`. Поток — `SCStream`, пиксели RGB8 по stdout (`L2F1`). Python `SCKFrameSource` реализует контурный `FrameSource`. Latest-only очередь. **Отклонено.** ctypes к ScreenCaptureKit. Автоматический запрос Screen Recording. Вшитые пиксели HUD. Считать запрошенные 60 FPS фактом.

## ADR-0013 — Запись эксперимента и раздельные часы

**Дата.** 2026-09-16  
**Статус.** Принято

**Контекст.** JSONL контура писал признаки и намерения синхронно, без кадров, без p50/p95/p99 по стадиям и без просмотра тика. Для разбора сбоя нужны кадр, признаки, команда и задержки одного момента.

**Решение.** Пакет `l2_brain.experiment`. Интервалы — monotonic. События — event clock. Latest-only очередь кадров. Async writer с подсчётом дропов. Кадры — npy sidecar. **Пересмотр.** Когда появится живой захват — добавить явное преобразование capture→event, не вычитать сырые метки устройств.

## ADR-0012 — Навигационный стенд с перспективной камерой

**Дата.** 2026-09-16  
**Статус.** Принято

**Контекст.** Нужна локальная оценка сенсомоторной навигации без клиента. Старый `SyntheticEnv` принимает `Action` и считает успехом `engage`. Правило 10 требует MotorIntent и разделения GT.

**Последствия.** Политика, которая видит `GroundTruth`, нелегальна. JSON сюиты всегда несёт `transfer_claim: false`.

**Отклонено.** Top-down как основной вид для потока. Успех по импульсу атаки. Один общий пул сцен без held-out.

**Пересмотр.** Если появится разрешённый игровой адаптер — стенд остаётся учебным, пока H10 не принята.

## ADR-0011 — Два контракта наблюдения и импульсные команды

**Дата.** 2026-09-16  
**Статус.** Принято

**Решение.** Контур живёт в `l2_brain.circuit` с `contracts.Frame` / `Observation` / `MotorIntent` / `Command` / `Effect`. Стендовые контроллеры не мигрируют в этом ходе. Импульсы `idle|fire`. Strafe выключен. Запись — JSONL без изображения. `replay` помечен как offline.

**Последствия.** Два типа с именем Observation: стендовый в `l2_brain.types`, контурный в `l2_brain.contracts`. Смешивать их в одном вызове нельзя.

**Отклонено.** Один универсальный Observation с кадром и признаками сразу. Pydantic. Живой InputBackend. Удержание attack как bool.

**Пересмотр.** Когда стендовая оценка перейдёт на тот же контур; когда появится разрешённый ввод (Q3).

## Уточнение оценки и восстановления — 2026-09-17

Сравниваем зрительные признаки с GT до применения следующего действия.
Наблюдаемость оценщика проверяет LOS/FOV центра цели и доступность кадра;
это геометрическая аппроксимация, не пиксельная разметка видимости.
При отсутствии доступных для оценки кадров `vision_miss_rate = null`.
`recovery_time_p50` в новых отчётах измеряется в секундах; старые артефакты
с тиками не изменяются. Версия метрик — `repair-20260917`.
GT физической блокировки использует применённую команду, если она записана;
для старых трейс-файлов остаётся fallback к `cmd_forward`.

Пропуск кадра обрывает базу временных признаков. Первый корректный кадр
после пропуска даёт статические признаки и устанавливает новую базу.
Память пеленга при этом стареет; это оценка по команде, не измерение поворота.
История попыток восстановления ограничена `attempt_memory`, а лимит
последовательных неудач сбрасывается после успеха или cooldown.
Доказательства и ограничения — `docs/evidence/repair-20260917/report.md`.
