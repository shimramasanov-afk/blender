# Дорожная карта

Этапы последовательные. Следующий не начинается по желанию «уже почти». Вход следующего — выход предыдущего плюс явная команда на живые шаги.

Оценка гипотез — по [assumptions.md](assumptions.md). Документы и интерфейсы — по [architecture.md](architecture.md).

## S0 — Каркас репозитория

**Цель.** Появиться как проект, а не как папка с планом.

**Делаем.**

- документы vision / architecture / assumptions / roadmap / decisions;
- пакет `l2_brain` с петлёй и тремя контроллерами;
- синтетическая среда;
- заглушки живого захвата и живого ввода, которые падают явно;
- зонд ScreenCaptureKit вне петли;
- `pytest` зелёный.

**Не делаем.** Захват игры, ввод в клиент, обучение больших сетей, MaleCNS, карты.

**Выход.**

- `pytest` проходит;
- `python -m l2_brain.evaluate --controller reactive --scenario open_field --episodes 4` печатает отчёт с `infer_ms` и `loop_ms`;
- в дереве нет исполняемого пути в живой клиент.

S0 закрывается этим деревом файлов, если тесты зелёные.

## S1 — Достоверный навигационный стенд, затем сравнение

**Вход.** S0 закрыт.

**Цель.** Сначала согласовать постановку, наблюдения и критерии. Не предпочесть SNN заранее. Полный MaleCNS приостановлен; ход 31 дал только синтетический экстракт (ADR-0038), не H11. Эвристический L1 на nav-sim **заморожен** (ADR-0030, 52/60). Изолированные `control/snn`, `control/gru` и `control/malecns` — не Frozen 60 и не закрытие H1/H3/H4. S2 не открыт.

**Основная линейка приёмки.** `nav-sim-v1` + `baseline-eval`. Таблица сверки: [integrity/01-roadmap.md](evidence/integrity/01-roadmap.md).

**Делаем сейчас (целостность).**

- зафиксировать и воспроизвести F14/F15 без перезаписи исходных JSON;
- разделить события остановки и неуспеха;
- описать наблюдаемость сцен;
- привести сцены восстановления и бюджет в соответствие с заявленными способностями;
- разделить ошибки зрения и управления диагностикой;
- проверить H15 абляцией, H16 — только если есть события блокировки.

**Дым S0, не вторая приёмка.** `l2-brain eval` на `SyntheticEnv` (`open_field`, `occluded`, `pursuit`, `memory_probe`) остаётся протоколом H1–H5/H9. Имена сцен не смешивать с nav-sim в одном отчёте. Официальные 20 эпизодов этих гипотез ещё не закрыты.

**Не делаем.** MPS «на всякий случай», полный MaleCNS в runtime, живой ввод, закрытие гипотезы юнит-тестом.

**Выход этого подэтапа.**

- определения исходов согласованы;
- сцены проверяют заявленное;
- исходные 23/60 воспроизводятся;
- рабочая политика без GT;
- H15/H16 помечены по факту прогона, не по наличию кода;
- обоснование, готов ли контур к сравнению с `recurrent`.

Старый выход «таблица трёх контроллеров закрывает H1» откладывается, пока целостность nav-sim не завершена. S2 по-прежнему ждёт закрытия H1 **или** явной команды, что живой захват важнее незакрытого H1; сейчас H1 не закрыта и S2 не открываем этим документом.

## S2 — Замер ScreenCaptureKit

**Вход.** S1 закрыт и H1 принята **или** явная команда на живой захват.
2026-09-17: команда есть — план [live-parallels-plan.md](live-parallels-plan.md).
Источник: видимое окно Parallels с Lineage 2, не скрытый гостевой стол.

**Цель.** Узнать частоту и стоимость кадра на M4 Max.

**Делаем.**

- доводим `macos/CaptureProbe` до записи интервалов;
- снимаем видимое окно (сначала любое стабильное, не обязательно игру);
- считаем H7;
- выбираем канал доставки кадра в Python (после цифр, не до).

**Не делаем.** Металл ради металла, захват скрытого окна как основной путь, подключение кадра к контроллеру «чтобы посмотреть».

**Выход.**

- evidence JSON с H7 — [live-s2/parallels-30s.json](evidence/live-s2/parallels-30s.json);
- решение: SCK годится как сенсор видимого окна (H7 принята, ADR-0041);
- `ScreenCaptureKitSource` остаётся выключенным из `evaluate` по умолчанию.

## S3 — Замер актуатора

**Вход.** S2 закрыт, H7 принята либо выбран другой легальный источник кадра.

**Цель.** Измерить задержку ввода и аварийный стоп. Не получить игровую политику.

**Делаем.**

- актуатор в безопасное окно (текст, пустой холст), не в клиент;
- press/release, нулевое действие, `emergency_stop`;
- оценка `act_ms` живого края.

**Не делаем.** Скрытие ввода, ввод в античит-контур, автологин, хранение паролей.

**Выход.**

- стоп проверен;
- есть p50/p95 события ввода;
- H8 ещё открыта (нет полного контура), но `act_ms` живого края известен.

## S4 — Живой клиент, узкий навык

**Вход.** S1–S3 закрыты **и** человек явно пишет, что S4 открыт.

**Цель.** Повторить один зрительный навык v1 на реальном окне. Не автономная жизнь персонажа.

**Делаем.**

- один класс, короткие эпизоды;
- тот же `Observation` / `Action`;
- разметка для H14;
- сравнение трёх контроллеров;
- попытка закрыть H8, H10, H14. H8 принята (F57); H10 и H14 открыты.

**Не делаем.** Квесты, диалоги, торговля, инвентарь, часовые маршруты, второй персонаж, MaleCNS как обязательный мозг, обход защиты.

**Выход.**

- живой отчёт с разделением `infer_ms` и полной задержки;
- H10 и H14 решены;
- список отказанных суждений («не застревает», «успевает всегда») остаётся в силе, если цифры их бьют.

## После v1 (не план работ)

Только если S4 дал принятый контур:

- обучение короткой памяти на записанных эпизодах;
- опциональный фрагмент MaleCNS как ещё один контроллер в том же протоколе;
- MPS/Metal, если H5 отклонена и H6 принята;
- расширение навыка, но не «весь класс игры».

Это не обязательства v1.

## Критерии, которые никогда не закрывают этап сами по себе

- красивое биологическое описание;
- зелёные тесты без `evaluate`;
- низкий `infer_ms` при неизвестном захвате;
- успешный прогон одного контроллера без двух других;
- демо на клиенте до S3.
