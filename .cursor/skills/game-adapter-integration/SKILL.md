# Game adapter integration

## Когда применять

Когда человек назвал игру и разрешил работу с её окном или тестовым сервером. Если игра, запуск или ввод неизвестны — не изобретать клиент.

## Входные данные

Обязательно установить или явно пометить `unknown`:

- игра и версия;
- способ запуска;
- доступные разрешённые интерфейсы;
- семантика камеры и движения;
- доступность телеметрии.

Если данных нет: реализовать интерфейсы и dry-run, не выдумывать интеграцию. Не подставлять недокументированные API.

## Порядок работы

1. Захват без управления. Только кадр и timestamp. Проверка разрешения ОС.
2. Запись наблюдений (вне политики, ограниченный объём).
3. Dry-run действий: лог намерения, ввод не уходит в клиент.
4. Ограниченная калибровка (масштаб курсора/окна), на безопасной цели, если ввод уже разрешён.
5. Проверка остановки: стоп отпускает удержание, новые команды не уходят.
6. Короткий навигационный эпизод.
7. Телеметрия — только разрешённый канал, не разбор защищённого потока «потому что удобно».
8. Боевой эпизод — после навигации, не вместо неё.

Не подключать новый ввод и новое обучение одновременно: сначала базовая управляемость.

Профиль игры хранить отдельно от общего кода. Общий контроллер не знает HUD этой игры.

## Проверки

- Нет кода обхода защиты, инъекций, патча клиента, перехвата учёток.
- Контроллер по-прежнему не вызывает ввод и захват.
- Устаревший кадр блокирует отправку.
- Dry-run прогнан до первого живого действия.
- Стоп проверен до навигационного эпизода.

## Результат

Профиль игры, калибровка (если была), ограничения, воспроизводимый сценарий запуска записи/dry-run. Пункты с `unknown` перечислены. Незакрытый ввод не описывать как «подключён».

## Когда завершено

Этап N закрыт только если выполнены его проверки. Нельзя закрыть «адаптер готов» на шаге 1. Боевой цикл без закрытой остановки и навигации не принимается.
