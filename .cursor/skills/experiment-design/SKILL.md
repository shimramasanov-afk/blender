# Experiment design

## Когда применять

Перед сравнением контроллеров, изменением обучения или заявлением о преимуществе архитектуры. Не применять, чтобы «описать исследование» без гипотезы и критерия отклонения.

## Входные данные

- Формулировка утверждения, которое хотят проверить.
- Список контроллеров или вариантов обучения.
- Набор сцен или ссылка на существующие сценарии стенда.
- Бюджет (эпизоды, запуски, время стены).
- Версия кода (`git rev-parse HEAD` если есть git; иначе короткое описание дерева).
- Если цифр ещё нет — не подставлять их.

## Порядок работы

1. Сформулировать проверяемую гипотезу (одно предложение + условие отклонения).
2. Выбрать базовый вариант (обычно текущий лучший простой контроллер).
3. Зафиксировать одинаковые условия: сцены, seed-последовательность, бюджет тика, энкодер, лимиты действия.
4. Определить метрики и бюджет. Отдельно `infer_ms` и полный тик. Для поведения — success, stuck, разбивка по сценам.
5. Разделить наборы сцен: лёгкие не смешивать в одно среднее с тупиками без таблицы по сценам.
6. Задать контрольные эксперименты (замороженные веса, перестановка меток, одинаковый random policy — что уместно).
7. Определить формат результата: JSON в `docs/evidence/` + строка статуса в `docs/assumptions.md`.
8. Запустить или явно указать, почему запуск ещё невозможен (нет стенда сцены, нет зависимости, нет разрешения).

Не подменять план общим исследовательским эссе.

## Проверки

- Гипотезу можно отклонить числами из шага 4.
- Held-out не используется для подбора.
- Число независимых запусков ≥ 3, если бюджет позволяет; иначе в плане написано почему 1.
- Нет обещания «не застревает» как критерия успеха без порога `stuck_rate`.
- Команды запуска ссылаются на существующие модули, не на выдуманные CLI.

## Результат

Файл плана (в чате и, если просили сохранить, `docs/evidence/<id>-plan.md`) со структурой:

```text
гипотеза / отклонение
база
независимые переменные
контрольные условия
метрики и пороги
сцены (train/val/held-out или только eval-stand)
seed и бюджет
команда запуска или причина «не запускаем»
путь будущего JSON
```

Конфигурация должна позволять повторить прогон без этого чата.

## Когда завершено

Есть план и воспроизводимая конфигурация. Прогон либо выполнен (цифры ещё не в каноне, пока нет файла evidence), либо явно отложен с причиной. Заявление о преимуществе без этого навыка не делается.
