# Apple Silicon profiling

## Когда применять

Перед включением MPS/Metal, сменой формата кадра «ради скорости» или после жалобы на задержку. Не применять как замену проектированию контроллера.

## Входные данные

- Устройство, версия macOS, версии Python/Swift/библиотек (снять командами в этом каталоге).
- Контур, который измеряют (стенд или зонд захвата — не смешивать в одну цифру).
- Размер задачи (H×W, batch=1 для онлайна).

## Порядок работы

1. Зафиксировать устройство, ОС и версии библиотек.
2. Измерить исходный полный контур. Раздельно: захват, копии, препроцесс, передача, compute, sync.
3. Найти основную стоимость (доля ≥ остальных).
4. Проверить поддержку нужных операций по документации выбранного бэкенда. MPS available ≠ op supported.
5. Сравнить CPU и GPU на реальных размерах, не на игрушечном матричном микробенче.
6. Выполнить одно обоснованное изменение.
7. Проверить корректность (численный допуск к CPU-эталону или байтовый кадр).
8. Повторить измерение тем же методом.
9. Провести длительный прогон (утечка памяти, дрейф latency). Для клиента — только на разрешённом этапе и отдельно от стенда.

Не обещать ускорение до измерения.

## Проверки

- Бенчмарк GPU синхронизирован.
- Показаны latency и throughput раздельно.
- Пик памяти записан.
- Если ускорение < порога полезности (нет смены бюджета тика) — изменение отклонено, не «оставлено как задел».

## Результат

Таблица до/после:

```text
этап контура | p50 | p95 | пик RAM | копии
решение: keep / revert
причина
```

Файл в `docs/evidence/` только после прогона.

## Когда завершено

Есть базовая линия, одно изменение, повторный замер и явное keep/revert. Оптимизация без таблицы считается несделанной.
